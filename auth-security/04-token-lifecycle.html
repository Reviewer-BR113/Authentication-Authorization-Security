4b

Where the browser keeps them

Access token in memory, sent as a Bearer header. Refresh token in a cookie JavaScript cannot touch.

internal/auth/cookie.go
http.SetCookie(w, &http.Cookie{
    Name:     "refresh_token",
    Value:    refresh,
    Path:     "/auth/refresh", // sent nowhere else
    MaxAge:   int(refreshTTL.Seconds()),
    HttpOnly: true,  // invisible to JavaScript
    Secure:   true,  // HTTPS only
    SameSite: http.SameSiteStrictMode, // no cross-site
})

4c

Rotation, reuse detection and the denylist

Every refresh swaps the old token for a new one. If an old one ever comes back, someone copied it.

internal/auth/refresh_store.go
func (s Store) Rotate(ctx context.Context,
    old string) (string, error) {
    v, err := s.rdb.GetDel(ctx, "rt:"+old).Result()
    if err == redis.Nil { // not live: reused or bogus?
        fam, _ := s.rdb.Get(ctx, "used:"+old).Result()
        if fam != "" {
            s.revokeFamily(ctx, fam)
            return "", ErrReuse
        }
        return "", ErrInvalid
    }
    if err != nil {
        return "", err // Redis down: fail closed
    }
    user, fam, _ := strings.Cut(v, "|")
    s.rdb.Set(ctx, "used:"+old, fam, refreshTTL)
    return s.Issue(ctx, user, fam), nil
}

// logout: deny this access token until it expires
s.rdb.Set(ctx, "deny:"+claims.ID, 1, time.Until(exp))

→GETDEL is atomic — two parallel refreshes cannot both win.
→Reuse = theft. Revoke the whole family: attacker and user are both logged out.
→Denylist TTL = time left on the token, so Redis never grows forever.
→If Redis errors, fail closed — refuse, never guess.
HANDS-ON · TOPIC 1

Stateless auth pipeline with dual tokens

  • POST /auth/login — bcrypt check → 15-min access JWT in the body + 7-day refresh in an HttpOnly cookie.
  • POST /auth/refresh — rotate the cookie, return a new access token; reuse → 401 and revoke the family.
  • POST /auth/logout — delete the refresh key, deny the access token's jti.
  • RequireAuth also rejects denied jtis.

Recap

Session 04 in four lines

1Access = short JWT, checked by signature. Refresh = long opaque token, checked in Redis.
2Refresh lives in an HttpOnly; Secure; SameSite=Strict cookie scoped to one path.
