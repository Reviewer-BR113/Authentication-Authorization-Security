10a

Secrets come from the environment — or the app won't start

Read config once at startup, validate it, and crash loudly if anything is missing.

✗ NEVER
  • const jwtSecret = "changeme"
  • .env committed to git
  • secrets in Dockerfile / README
  • keys pasted into Slack
✓ INSTEAD
  • os.Getenv at startup
  • .env in .gitignore, .env.example committed
  • secret manager / platform env vars
  • gitleaks in CI
internal/config/config.go
type Config struct {
    Addr      string
    DBURL     string
    JWTSecret []byte
}

func Load() (Config, error) {
    c := Config{
        Addr:      getenv("ADDR", ":8080"),
        DBURL:     os.Getenv("DATABASE_URL"),
        JWTSecret: []byte(os.Getenv("JWT_SECRET")),
    }
    var errs []error
    if c.DBURL == "" {
        errs = append(errs, errors.New("DATABASE_URL is required"))
    }
    if len(c.JWTSecret) < 32 {
        errs = append(errs, errors.New("JWT_SECRET must be ≥ 32 bytes"))
    }
    return c, errors.Join(errs...)
}
go run ./demos/10 · JWT_SECRET=changeme, no DATABASE_URL — then fixed
refusing to start:
DATABASE_URL is required
JWT_SECRET must be ≥ 32 bytes
ok: true addr: :8080 secret bytes: 32
→Fail at boot, not at the first request. A missing secret should never become a running server.
→A secret that ever reached git is leaked — deleting the file keeps it in history. Rotate it.

10b

What leaves the server: responses and logs

The same user struct, serialised and logged — before and after. All real output.

internal/user/user.go
type User struct {
    ID           int       `json:"id"`
    Email        string    `json:"email"`
    PasswordHash string    `json:"-"`   // never serialised
    Role         string    `json:"role"`
    ResetToken   string    `json:"-"`
    CreatedAt    time.Time `json:"created_at"`
}

// LogValue: what slog prints when a User is logged.
func (u User) LogValue() slog.Value {
    return slog.GroupValue(
        slog.Int("id", u.ID),
        slog.String("role", u.Role),
    )
}

type Secret string

func (Secret) LogValue() slog.Value {
    return slog.StringValue("[REDACTED]")
}
→json:"-" is the safety net. Better still: a separate UserResponse struct that only has public fields.
→slog.LogValuer makes the type redact itself — nobody has to remember at every log call.
→Never log request bodies of /login, /register or /auth/refresh.

→Migrations run as migrator in CI; the running API connects as api_app.
→The audit log is append-only for the API — an attacker can't erase their tracks.
→Same rule for API keys: scoped (read-only, one service), short-lived, rotatable.
