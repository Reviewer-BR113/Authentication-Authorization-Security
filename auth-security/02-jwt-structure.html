Session 02 · 🎫 Stateless auth

JWT Structure

A signed note the server can trust without looking anything up.

✓
2athree parts, one signature
✓
2bstandard claims

2a

Header · Payload · Signature

Take a real token apart, then try to forge one. Walk it with Next.

→Base64 is encoding, not encryption. Anyone holding the token can read the payload.
✗Never put passwords, emails or other private data in the payload.
✓The signature makes it tamper-proof — change one character and verification fails.
→Stateless: the server checks the signature with its secret — no database lookup per request.

2b

The claims every access token needs

Registered claim names are short on purpose — the token travels with every request.

demos/02/main.go
import "github.com/golang-jwt/jwt/v5"

claims := jwt.MapClaims{
    "sub":  "42",
    "role": "user",
    "iat":  now.Unix(),
    "exp":  now.Add(15 * time.Minute).Unix(),
}
tok := jwt.NewWithClaims(jwt.SigningMethodHS256, claims)
s, err := tok.SignedString(secret)
go run ./demos/02
header  {"alg":"HS256","typ":"JWT"}
payload {"exp":1790000900,"iat":1790000000,"role":"user","sub":"42"}
forged :   token signature is invalid: signature is invalid
genuine:   <nil>
16m later: token has invalid claims: token is expired
→exp is checked by the library automatically — an expired token fails Parse.
→Keep access tokens short-lived (5–15 min): a stolen token is only useful until exp.
→The secret comes from config, is ≥ 32 random bytes, and never appears in code.
