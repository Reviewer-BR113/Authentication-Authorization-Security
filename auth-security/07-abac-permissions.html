7b

A policy is a list of rules, checked in order

Each rule matches or doesn't; the first match decides; nothing matching means no.

internal/authz/policy.go
type Req struct {
    Sub Subject   // id, role, dept, grants
    Act string    // "read", "edit", "publish"
    Res Resource  // owner, dept, status
    Now time.Time // environment
}

type Rule struct {
    Name  string
    Match func(q Req) bool
    Allow bool
}

var policy = []Rule{
    {"publish needs explicit grant", func(q Req) bool {
        return q.Act == "publish" &&
            !slices.Contains(q.Sub.Grants, "doc:publish")
    }, false},
    {"owner edits own draft", func(q Req) bool {
        return q.Act == "edit" && q.Sub.ID == q.Res.OwnerID
    }, true},
    // … 5 more rules
}

func Decide(q Req) (bool, string) {
    for _, rule := range policy {
        if rule.Match(q) {
            return rule.Allow, rule.Name
        }
    }
    return false, "default deny"
}

→Deny rules go first. Order is part of the policy — the second run proves it.
→Explicit grants (doc:publish) give one user a power their role doesn't have — store them in a user_permissions table.
→Return the rule name with the decision and log it — "why was I denied?" becomes answerable.
